# Flowsy deployment and Android APK

This project is prepared to host the NestJS API and PostgreSQL on Render, then build an installable Android APK with Expo EAS.

## 1. Deploy the API and database

The Render Blueprint is in `render.yaml`. It creates a Frankfurt API service and PostgreSQL 17 database, generates strong JWT secrets, applies Prisma migrations before starting the API, and checks `/api/v1/health`.

The Blueprint uses paid Render plans so the API stays awake and the database does not expire. Review the current service and database prices in Render before confirming Blueprint creation. Free Render web services sleep after inactivity, and free Postgres databases expire after 30 days, so they are unsuitable for an app you plan to use regularly.

1. Push this repository to a private GitHub or GitLab repository. There is no Git remote configured in this checkout yet.
2. In Render, choose **New → Blueprint**, connect that repository, and select its `render.yaml`.
3. Review the estimated monthly cost, then create the resources.
4. Wait for the first deploy to finish. Check `https://flowsy-api.onrender.com/api/v1/health` and `/api/docs`.

If Render assigns a different public hostname, update `CORS_ORIGIN` in Render and the API URL in `mobile/eas.json` to match it. Keep JWT secrets generated by Render and never copy local `.env` values into the hosted service.

The production database starts empty. Do not run the development demo seed against it; users can register in the app and receive their normal starter data.

## 2. Build an installable APK

The `preview` EAS profile produces an internal Android APK and points it at the hosted API. The app name and Android package identifier are set to Flowsy values.

From PowerShell:

```powershell
cd mobile
npx eas-cli login
npx eas-cli build:configure
npx eas-cli build --platform android --profile preview
```

EAS will ask to link this app to an Expo project and configure Android signing the first time. After the cloud build finishes, open the build URL on your Android phone and install the APK. Android may ask you to allow installs from the browser used to download it.

For later builds, use the same build command. EAS stores the signing credentials for this Expo project so installed updates keep the same app identity.

## 3. Local development

The production API URL is set only in the EAS profiles. Local Expo development continues to use the existing LAN/emulator URL fallback unless `EXPO_PUBLIC_API_URL` is set in `mobile/.env`.
